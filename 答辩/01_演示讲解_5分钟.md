# StoryForge 答辩演示讲解文档（5 分钟）

> 演示地址：https://storyforge.fun
> 目标：在 5 分钟内完整走一遍「官网（详细）→ 登录 → 市场 → 故事体验（角色卡+世界卡+人设面具）→ 故事工作台 → 导出 → 发布 → 互动」核心链路，边操作边讲解。

---

## 一、演示前准备（务必提前完成）

| # | 事项 | 说明 | 为什么 |
|---|------|------|--------|
| 1 | 域名可达 | 浏览器打开 https://storyforge.fun 确认能访问 | 避免演示时网络翻车 |
| 2 | 提前注册登录 | 提前注册一个演示账号并保持登录（或提前记住账号密码） | 登录页有图形验证/限流，现场注册浪费时间 |
| 3 | 配置 AI Key | 「设置 → AI 模型管理」提前加一个 **DeepSeek**（或 OpenAI/Ollama）并设为默认 | 没配 Key 只会输出占位 mock 文本，效果大打折扣 |
| 4 | 准备示例故事 | 提前创建 1 个「故事」（含 2~3 个章节大纲） | 故事体验与工作台演示的主体 |
| 5 | 准备并绑定卡片 | 提前创建 1 个「角色卡」+ 1 个「世界卡」，并在故事工作台「引入」绑定到该故事 | 故事体验时才能体现「世界观 + NPC 人设」注入 |
| 6 | 准备人设面具 | 提前创建 1 个「人设面具」（如「巡夜人」） | 故事体验必须选面具才能进入 |
| 7 | 发布一个作品 | 提前把示例故事发布到市场 | 演示市场/点赞/关注时有素材 |
| 8 | 检查 PDF 字体 | 若演示 PDF 导出，确认服务器 `storage/fonts/NotoSansSC-Regular.otf` 存在 | 否则 PDF 回退 Markdown |
| 9 | 准备第二个账号 | 准备一个「访客账号」用于演示点赞/关注/通知 | 演示互动闭环需要第二个身份 |

> ⚠️ 最关键的准备：**AI Key** 和**一套绑定好的「故事 + 角色卡 + 世界卡 + 人设面具」**。前者决定 AI 输出是否真实，后者是第 3 步「故事体验」能否讲清楚的前提。建议用 DeepSeek（成本低、OpenAI 兼容、`Base URL = https://api.deepseek.com/v1`）。

## 三、分步演示脚本

### 第 0 步 · 官网（详细，50s）

**操作**：浏览器打开 https://storyforge.fun，停留在**官网落地页**（未登录状态），从上到下慢慢滚动。

**讲解话语**：

> 各位老师好，我是 XXX。今天演示的项目是 **StoryForge——基于 AI 大模型的交互式小说创作平台**。
>
> 打开网址先看到官网落地页。顶部一句话定位：**「戴上面具，走进别人写的世界」**。这句话点出核心玩法：**作者**产出故事、角色、世界三种内容，**读者**选一个「人设面具」扮演某个身份，走进别人写好的故事里。
>
> 右边这个对话窗口就是产品的真实交互形态——注意三个细节：作品会**先说开场语**（不是等你先发消息）；左上角显示你戴的「面具」身份；右上角是「**好感度**」进度。也就是说，你进入的不是一个空白对话框，而是一个**有舞台、有角色、有关系**的场景。
>
> 往下滚是三个模块：**「能做什么」**——人设面具、故事是舞台、好感会生长、下载到本地；**「如何开始」**——发现、下载、戴上面具、互动，四步进入故事；**「内容类型」**——故事卡、角色卡、世界卡三种可上架，人设面具只属于你自己。
>
> 官网的作用是让陌生访客快速理解产品价值；登录后会自动进入产品主界面。下面我从登录开始，完整走一遍。

---

### 第 1 步 · 登录（15s）

**操作**：点官网右上角「登录」→ 进入 /login，输入账号密码登录（登录成功后跳转 /market）。

**讲解话语**：

> 平台账号体系是**用户名 + 密码**登录。密码用 **scrypt 加盐哈希**存储，登录成功后签发 **JWT**，放在 **HttpOnly Cookie** 里，前端 JS 拿不到，天然防 XSS 窃取；登录/注册还做了**限流**防暴力破解。

---

### 第 2 步 · 市场（30s）

**操作**：登录后进入 /market，切换「故事 / 角色 / 世界」三个 Tab，点「推荐 / 最新 / 更新」排序，演示一次搜索。

**讲解话语**：

> 登录后就进入产品主界面「市场」。所有用户发布的作品在这里展示，分**故事、角色、世界**三类。
>
> 「推荐」排序是我自己实现的**轻量推荐引擎**——`0.45×点赞 + 0.25×作者热度 + 0.20×标签匹配 + 0.10×新鲜度` 加权打分，登录用户还会做**个性化重排**（基于你点赞过的标签画像）。每张卡片都能点赞、收藏、关注作者。

---

### 第 3 步 · 故事体验（核心，95s）

**操作**：进入 /stories/[id]（示例故事）→ 点「互动体验」→ 选择人设面具「巡夜人」→ 点「开始体验」→ 发送一条指令 → 展示 AI 流式生成 → 中途点一次「停止」。

**讲解话语**：

> 这是全项目最核心的部分——**故事体验**。注意这个演示同时用到了四种内容资产：
> 1. 这个故事**绑定了一张世界卡**（世界观：赛博朋克、科技垄断、霓虹都市）；
> 2. 绑定了**角色卡**（V、强尼银手这些 NPC，各有人设和说话风格）；
> 3. 我选了「**人设面具——巡夜人**」作为我扮演的身份。
>
> 点「开始体验」后，注意**故事会先开口说开场语**，而不是等我先发消息。
>
> （发送指令）现在我说一句「我是今晚的巡夜人，这封信我送到」。看右侧，AI 是**逐字流式**返回的，像真人打字。这里的关键技术是：发送前会把**世界观设定、NPC 人设、我的人设面具、文风约束、世界知识库 RAG 召回的资料、最近 12 条对话**全部组装进 Prompt——所以 AI 会「守设定、不串戏」。
>
> 注意右上角，**好感度**在随对话增长，AI 的语气亲密度也跟着变。再看两个细节：我可以随时点「**停止**」中断生成；如果主模型挂了，后端会**自动切到备用模型**，保证不断流。这套对话引擎同样复用在角色独聊、世界探索里。

---

### 第 4 步 · 故事工作台（40s）

**操作**：进入 /stories/[id]/edit，展示：章节大纲树（添加子章节/拖动排序）→ 人物关系图谱（d3）→ 引入角色/世界卡 → 三个「创作辅助」按钮。

**讲解话语**：

> 对话只是「生成」，要写一本结构完整的书，还需要**结构化创作**。这是故事工作台：
>
> 左侧是**章节大纲树**，支持无限层级、拖拽排序，每章可写摘要；下面是**人物关系图谱**，用 d3 做的，能定义角色间敌对/盟友/恋人等关系；再往下就是刚才体验里用到的**引入角色卡、世界卡**——AI 写作会自动参考这些设定。
>
> 右边三个按钮是「**创作辅助**」：**冲突检测**（无魔法世界出现法术，会给出 P0/P1/P2 分级提示）、**一致性校验**（检查角色身份、时间线是否矛盾）、**文风保持**（抽取已有段落文风特征注入后续生成，保证全书风格统一）。

---

### 第 5 步 · 导出（20s）

**操作**：工作台顶部「导出」→ 选 EPUB（或 PDF）。

**讲解话语**：

> 内容写好后一键导出 **EPUB / PDF / TXT / Markdown**。EPUB 用 JSZip 按 EPUB 3 规范打包（含封面、目录、分章节），PDF 用 PDFKit 自动分页、加页眉页脚，中文做了 CJK 字体处理；目标格式失败会自动回退 Markdown 备份，保证内容不丢。

---

### 第 6 步 · 发布 + 互动闭环（40s）

**操作**：进入 /my → 点「发布」→ 回 /market 刷新看作品上架 → 用另一账号点赞/关注 → 回 /my 看通知。

**讲解话语**：

> 最后走**发布闭环**：在「我的」把故事发布上架，发布前先过一层**内容安全过滤**；回市场刷新就能看到作品。
>
> 用另一个账号点赞、关注，原作者的「通知中心」实时收到通知——点赞、关注、收藏这些轻互动同时反哺推荐排序。这样「创作 → 生成 → 发布 → 被体验 → 互动」就形成完整闭环。

---

### 第 7 步 · 收尾（10s）

**讲解话语**：

> 以上就是 StoryForge 的完整演示。一句话总结：我用 **Next.js 全栈 + SQLite + 多模型 AI 接入 + RAG 检索**，实现了一个「人人可用 AI 写小说」的平台，把最难的「写」变成了最有趣的「聊」。谢谢各位老师，请指正！

## 四、讲解时的「技术包袱」速记（可选，穿插说）

| 话题 | 一句话亮点 |
|------|-----------|
| 官网 | 落地页分流：未登录展示营销页，登录跳 /market |
| 架构 | 四层：体验接入层 / 业务服务层 / AI 编排层 / 存储层，前后端一体 |
| 人格面具 | 用户私有身份，注入 Prompt 让 AI 把「用户」当该身份 |
| AI 接入 | OpenAI 兼容协议统一抽象，DeepSeek/OpenAI/Anthropic/Ollama/自定义 五类 |
| 流式 | SSE + 心跳 15s + 180s 超时 + 停止生成 + 降级链 |
| RAG | 知识库词条向量化，余弦相似度检索，无向量库也能关键词兜底 |
| 推荐 | 加权打分 + 用户标签画像 + 时间衰减 |
| 安全 | JWT HttpOnly Cookie + scrypt 密码 + CSRF 校验 + 防重放 + 内容过滤 + 限流 |
| 存储 | SQLite WAL 模式 + 幂等迁移，预留 PostgreSQL 迁移脚本 |
| 部署 | Docker 多阶段构建 + Nginx 反代 + 健康检查 |

## 五、常见翻车点 & 应急话术

| 翻车点 | 应急处理 |
|--------|----------|
| AI 输出是 mock 占位文本 | 「为了演示稳定性我先用占位输出，真实配置 API Key 后走大模型，我现场切一下 DeepSeek」→ 立即去设置页配 Key |
| 流式卡住/超时 | 点「停止」，说「模型响应较慢，这正是我做了超时重试和降级链的原因」 |
| 没人设面具/没绑定卡片 | 说「这套体验需要先有故事+角色/世界卡+面具，我提前都准备好了」；若真没有，快速去「创作」建一个面具 |
| PDF 导出回退 Markdown | 「服务器缺中文字体，自动回退 Markdown 备份，这正是我的容错策略」 |
| 市场空列表 | 提前发布过就不会空；仍空就现场在「我的」点发布 |
| 网络抖动 | 保持淡定，说「演示环境网络有波动，代码层面我做了指数退避重试」 |
