# StoryForge 答辩演示讲解文档（5 分钟）

> 演示地址：https://storyforge.fun
> 目标：在 5 分钟内完整走一遍「官网 → 登录 → 市场 → 创作 → AI 对话生成 → 大纲/关系图 → 导出 → 发布 → 互动」核心链路，边操作边讲解。

---

## 一、演示前准备（务必提前完成）

| 事项 | 说明 | 为什么 |
|------|------|--------|
| 1. 域名可达 | 浏览器打开 https://storyforge.fun 确认能访问 | 避免演示时网络翻车 |
| 2. 提前注册登录 | 提前注册一个演示账号并保持登录（或提前记住账号密码） | 登录页有图形验证/限流，现场注册会浪费时间 |
| 3. 配置 AI Key | 在「设置 → AI 模型管理」提前添加一个 **DeepSeek**（或 OpenAI/Ollama）模型并设为默认 | 未配置 Key 时 AI 只会输出「占位 mock 文本」，效果大打折扣 |
| 4. 准备示例内容 | 提前创建 1 个「角色卡」、1 个「世界卡」、1 个「故事」（含 2~3 个章节大纲） | 现场从零建会超时 |
| 5. 发布一个作品 | 提前把示例故事发布到市场，让市场列表有内容可点 | 演示市场/点赞/关注时有素材 |
| 6. 检查 PDF 字体 | 若演示 PDF 导出，确认服务器 `storage/fonts/NotoSansSC-Regular.otf` 存在 | 否则 PDF 会回退成 Markdown |
| 7. 准备另一个账号 | 准备一个「访客账号」用于演示点赞/关注/通知 | 演示互动闭环需要第二个身份 |

> ⚠️ 最关键的准备：**AI Key**。整个产品最亮眼的是「对话式 AI 生成」，如果只有 mock 输出，评委看不出技术含量。建议用 DeepSeek（成本低、OpenAI 兼容、`Base URL = https://api.deepseek.com/v1`）。

## 三、分步演示脚本

### 第 0 步 · 开场 + 官网（30s）

**操作**：浏览器打开 https://storyforge.fun，停留在**官网落地页**（未登录状态）。

**讲解话语**：

> 各位老师好，我是 XXX。今天给大家演示我做的项目 **StoryForge——一个基于 AI 大模型的交互式小说创作平台**。
>
> 打开网址先看到的是**官网落地页**：顶部一句话定位「戴上面具，走进别人写的世界」，往下滚动是「能做什么」「如何开始」「内容类型」三个模块，用卡片把产品的核心玩法讲清楚；登录后会自动进入产品主界面「市场」。
>
> 它的核心想法是：**把「酒馆式角色扮演」的玩法，改造成面向大众的小说创作工具**——用户通过和 AI 对话，像「导演」一样指挥 AI 生成世界观、角色和剧情，一键导出成电子书，还能上架到市场让别人「体验」你的故事。
>
> 接下来我从登录开始，完整走一遍产品核心链路。

---

### 第 1 步 · 登录/注册（20s）

**操作**：点击官网右上角「登录」→ 进入 /login，输入账号密码登录（登录成功后跳转 /market）。

**讲解话语**：

> 平台的账号体系是**用户名 + 密码**登录（Google OAuth 在 MVP 阶段已停用）。密码用 **scrypt 加盐哈希**存储，登录成功后签发 **JWT**，放在 **HttpOnly Cookie** 里，前端 JS 拿不到，天然防 XSS 窃取。同时做了登录/注册的**限流**，防止暴力破解。

---

### 第 2 步 · 市场（30s）

**操作**：登录后进入 /market，切换「故事 / 角色 / 世界」三个 Tab，点一下「推荐 / 最新 / 更新」排序，再演示一次搜索。

**讲解话语**：

> 登录后就进入产品主界面「市场」。所有用户发布的作品在这里展示，分**故事、角色、世界**三类。
>
> 排序里有个「推荐」，是我自己实现的一个**轻量推荐引擎**——按 `0.45×点赞 + 0.25×作者热度 + 0.20×标签匹配 + 0.10×新鲜度` 加权打分，登录用户还会做**个性化重排**（基于你点赞过的标签画像）。下面每一张卡片都能直接点赞、收藏、关注作者。

---

### 第 3 步 · 创作角色卡（50s）

**操作**：点侧边栏「创作」→ 切到「角色卡」Tab → 填名称/简介/性格/外貌/背景/说话风格 → 点「创建角色卡」→ 进入角色详情页。

**讲解话语**：

> 点「创作」进入创作工作台，这里能创建四种资产：**故事、角色卡、世界卡、人设面具**。
>
> 我先演示创建一个**角色卡**。角色卡是平台的最小创作单元，包含性格、外貌、背景、说话风格、开场语等字段。这里有个细节：我支持**从 Word/PDF/TXT 文档直接导入**，自动解析出角色设定填进表单，省去手动录入。
>
> 创建完进入详情页，除了编辑，还能直接和这个角色**独立对话**，测试角色表现、调整人设。

---

### 第 4 步 · AI 对话生成（核心，80s）

**操作**：点角色详情页的「与角色对话」→ 进入 /characters/[id]/chat → 发送一条指令 → 展示 AI 流式打字机输出 → 中途点一次「停止」。

**讲解话语**：

> 这是全项目最核心的部分——**对话式 AI 生成**。我给角色发一句「你愿意讲讲你的过去吗」，注意看右侧，AI 是**逐字流式**返回的，体验像真人打字。
>
> 技术上有几个关键点：
> 1. 前端用 **fetch 流式读取 + SSE**，后端按 `data: {...}` 事件流逐段推送，每 15 秒发一次心跳保活；
> 2. 发送前会**分层组装 Prompt**：系统硬约束（合规、禁止 OOC）→ 世界观设定 → 角色人设 → 文风约束 → 从世界知识库 **RAG 召回**的相关资料 → 最近 12 条历史对话 → 当前指令；
> 3. 我做了**多模型降级链**：主模型失败自动切换备模型，全失败才回退到占位输出；
> 4. 支持**中途停止生成**、**多会话并行**、以及一个「**好感度**」机制——AI 会根据你和角色的互动动态调整语气亲密度。
>
> （快速切换）同样一套对话引擎也用在**故事体验**里：你选一个「人设面具」扮演某个身份，进入别人写的故事，故事里的角色都作为 NPC 和你互动，AI 帮你生成属于你自己的分支剧情。

---

### 第 5 步 · 故事工作台（40s）

**操作**：进入 /stories/[id]/edit，展示：章节大纲树（添加子章节/拖动排序）→ 人物关系图谱（d3）→ 引入角色/世界卡 → 三个「创作辅助」按钮（冲突检测/一致性校验/文风保持）。

**讲解话语**：

> 对话只是「生成」，要写一本结构完整的书，还需要**结构化创作**。这是故事工作台：
>
> 左侧是**章节大纲树**，支持无限层级、拖拽排序，每章可写摘要；下面是**人物关系图谱**，用 d3 做的，能定义角色之间的敌对/盟友/恋人等关系；再往下可以把之前创建的角色卡、世界卡**引入**到这个故事里，AI 写作时会自动参考这些设定。
>
> 右边这三个按钮是「**创作辅助**」：**冲突检测**（比如无魔法世界出现了法术，会给出 P0/P1/P2 分级提示）、**一致性校验**（检查角色身份、时间线是否矛盾）、**文风保持**（抽取已有段落的文风特征，注入后续生成，保证全书风格统一）。

---

### 第 6 步 · 导出（20s）

**操作**：点工作台顶部的「导出」，选 EPUB（或 PDF）。

**讲解话语**：

> 内容写好后，点导出，支持 **EPUB / PDF / TXT / Markdown** 四种格式，一键生成可直接发布的电子书。EPUB 用 JSZip 按 EPUB 3 规范打包（含封面、目录、分章节），PDF 用 PDFKit 自动分页、加页眉页脚，中文还做了 CJK 字体处理；如果目标格式失败会自动回退成 Markdown 备份，保证内容不丢。

---

### 第 7 步 · 发布 + 互动闭环（20s）

**操作**：进入 /my → 点「发布」→ 回到 /market 刷新，能看到作品上架 → 用另一个账号演示点赞/关注 → 回到 /my 看通知。

**讲解话语**：

> 最后走一遍**发布闭环**：在「我的」里把故事发布上架，发布时会先经过一层**内容安全过滤**；回到市场刷新就能看到作品。
>
> 用另一个账号点赞、关注，原作者的「通知中心」会实时收到通知——点赞、关注、收藏这些轻互动会同时反哺推荐排序。这样从「创作 → 生成 → 发布 → 被体验 → 互动」就形成了完整闭环。

---

### 第 8 步 · 收尾（10s）

**讲解话语**：

> 以上就是 StoryForge 的完整演示。一句话总结：我用 **Next.js 全栈 + SQLite + 多模型 AI 接入 + RAG 检索** 实现了一个「人人可用 AI 写小说」的平台，把最难的「写」变成了最有趣的「聊」。谢谢各位老师，请指正！

## 四、讲解时的「技术包袱」速记（可选，穿插说）

| 话题 | 一句话亮点 |
|------|-----------|
| 架构 | 四层：体验接入层 / 业务服务层 / AI 编排层 / 存储层，前后端一体 |
| AI 接入 | OpenAI 兼容协议统一抽象，DeepSeek/OpenAI/Anthropic/Ollama/自定义 五类 |
| 流式 | SSE + 心跳 15s + 180s 超时 + 停止生成 + 降级链 |
| RAG | 知识库词条向量化，余弦相似度检索，无向量库也能关键词兜底 |
| 推荐 | 加权打分 + 用户标签画像 + 时间衰减 |
| 安全 | JWT HttpOnly Cookie + scrypt 密码 + CSRF 校验 + 防重放 + 内容过滤 + 限流 |
| 存储 | SQLite WAL 模式 + 幂等迁移，预留 PostgreSQL 迁移脚本 |
| 部署 | Docker 多阶段构建 + Nginx 反代 + 健康检查 |

## 五、常见翻车点 & 应急话术

| 翻车点 | 应急处理 |
|--------|----------|
| AI 输出是 mock 占位文本 | 「这里为了演示稳定性我先用占位输出，真实配置 API Key 后走大模型，我现场切一下 DeepSeek」→ 立刻去设置页配 Key |
| 流式卡住/超时 | 点「停止」，说「模型响应较慢，这正是我做了超时重试和降级链的原因」 |
| PDF 导出回退 Markdown | 「服务器上缺中文字体，自动回退成了 Markdown 备份，这正是我设计的容错策略」 |
| 市场空列表 | 提前发布过作品就不会空；若仍空，现场在「我的」点一下发布即可 |
| 网络抖动 | 保持淡定，说「演示环境网络有波动，代码层面我做了指数退避重试」 |
