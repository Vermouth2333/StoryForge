# StoryForge 技术报告

> 项目名称：StoryForge —— 基于 AI 大模型的交互式小说创作平台
> 线上地址：https://storyforge.fun
> 技术栈：Next.js 16 (App Router) + React 19 + TypeScript + SQLite + Redis + 多模型 AI 接入

---

## 一、项目概述

StoryForge 是一个「酒馆式对话 + AI 创作」的小说创作平台。它将 SillyTavern 这类极客向的角色扮演引擎产品化，让普通用户通过「与 AI 对话」的方式创作结构完整的小说，并可导出为电子书、发布到平台市场供他人体验。

**核心能力闭环**：

```
创作（角色卡/世界卡/故事） → AI 对话生成（流式） → 结构化编辑（大纲/关系图）
        → 导出（EPUB/PDF/TXT/MD） → 发布市场 → 体验/点赞/关注/通知
```

## 四、核心模块详细设计

### 4.1 用户与鉴权

**注册/登录**（`app/api/auth/register|login/route.ts`）：

- 用户名 + 密码（Google OAuth 在 MVP 已停用，`/api/auth/google` 直接重定向登录页）。
- 密码存储：`lib/password.ts` 用 Node 内置 `scrypt`（N=16384, r=8, p=1）加 16 字节随机盐，格式 `scrypt$N$r$p$saltHex$hashHex`，验证用 `timingSafeEqual` 防时序攻击。
- 会话：登录成功签发 JWT（`lib/session-jwt.ts`，HS256，7 天过期，payload 只含 `uid`），写入 HttpOnly Cookie `sf_session`；`lib/auth.ts` 的 `getCurrentUserId()` 优先解析 Cookie，兼容调试头 `x-user-id`。
- 限流：`lib/rate-limit.ts` 固定时间窗计数（登录 30 次/15 分钟，注册 10 次/小时），进程内 Map 实现，注释明确「多实例需 Redis」。

**用户设置**（`app/(main)/settings`）：头像（sharp 缩略图）、作者简介（≤500 字）、手机号脱敏、AI 模型管理、账号注销（`lib/account-deletion.ts`：二次确认 → `status=deleted` → 作品匿名保留或删除 → 清互动数据）。

### 4.2 AI 生成引擎

**统一 Provider 抽象**（`lib/ai-provider.ts`）：

- 所有模型统一到 OpenAI 兼容 `/chat/completions` 接口，`resolveProvider()` 解析 Base URL + API Key（用户配置优先，回退环境变量）。
- 支持 `openai / anthropic / deepseek / ollama / custom` 五类，做端点归一化（如 DeepSeek 自动补 `/v1`）。
- `streamChat()` 用 `fetch` 流式读取，逐段 `yield` 增量文本；`completeChat()` 提供非流式一次性生成。
- **未配置 Key 时 `resolveProvider()` 返回 null**，调用方回退到占位输出，保证演示/无 Key 环境可用。

**多模型降级链**（`lib/model-manager.ts`）：

- 用户模型存 `user_models` 表，支持增删改、默认模型（`user_settings`）、会话级模型（`chat_sessions.model_id`）。
- `getFallbackModelIds()` 生成「主模型 + 其余已启用模型」的降级序列。

**流式生成主流程**（`app/api/chat/sessions/[id]/generate/route.ts`，SSE）：

1. zod 校验 `content`（1~5000 字）+ 内容过滤；
2. 登录校验 + 用户/双 IP 限流（45 次/分、120 次/分）；
3. 读取会话 → 组装上下文（`buildChatContext`）→ 插入好感度提示；
4. 写入用户消息，构造 `ReadableStream`：
   - **心跳**：每 15s 发 `heartbeat`；
   - **总超时**：180s 强制结束；
   - **降级链**：主模型失败且无输出时切备模型，全失败回退 mock；
   - **停止生成**：`lib/chat-state.ts` 内存标志 + `AbortController`，中途点击「停止」→ 发 `done(reason:"stopped", incomplete:true)`；
   - 生成结束后落库 assistant 消息（含 token 估算、耗时、模型名），更新会话时间；
   - **好感度记账**：`lib/affinity.ts` 根据互动估算情感增量并更新；
   - **冲突检测**：生成内容非阻塞地跑 `conflictDetector`，命中 P0/P1 追加 `conflict` 事件。

**SSE 事件协议**：

```
data: {"type":"content","content":"...","seq":1}
data: {"type":"heartbeat","ts":1714548000}
data: {"type":"conflict","blocking":true,"conflicts":[...]}
data: {"type":"done","message_id":"msg_123","affinity":{...}}
```

### 4.3 Prompt 分层组装与 RAG

`lib/prompt-context.ts` 的 `buildChatContext()` 按以下顺序组装 messages：

1. **系统层（硬约束）**：合规（禁止涉政/涉黄/涉暴）、禁止 OOC、世界观不得自相矛盾、中文小说化叙述；
2. **世界观层**：世界名称/简介/设定要点（若会话绑定世界）；
3. **人设面具层**：用户扮演身份（仅故事体验）；
4. **角色层（NPC）**：单个焦点角色，或故事中引入的全部角色（≤20）；
5. **文风层**：`story_style_anchors` 表里的文风特征摘要；
6. **参考资料层（RAG）**：按当前指令从世界知识库检索的 Top 3 词条；
7. **历史对话**：最近 12 条 user/assistant 消息；
8. **当前指令**。

**RAG 实现**（`lib/rag-engine.ts`）：

- 知识库词条持久化到 `rag_vectors` 表（含 content、tags、可选 embedding）；
- 有 `OPENAI_API_KEY` 时用 `text-embedding-3-small` 生成向量，检索用**余弦相似度**；
- 无向量时**自动退化到关键词匹配**（中文 bi-gram 分词），保证任何环境可用；
- 每次检索用独立索引实例先 `sync` 再查，避免跨会话污染；检索失败不影响主流程（try/catch 吞掉）。

### 4.4 创作辅助（AI 一致性三件套）

| 模块 | 文件 | 核心逻辑 |
|------|------|---------|
| 冲突检测 | `lib/conflict-detector.ts` | 规则引擎（关键词/正则）+ AI 辅助两段式；冲突分 P0（违反世界硬规则）/P1（OOC）/P2（语气偏移）；P0/P1 拦截并给解释式改写建议 |
| 一致性校验 | `lib/consistency-checker.ts` | 校验角色身份/关系、时间顺序、地点约束；规则库为主；输出 `violations` + 可选 `autoFixDraft` |
| 文风保持器 | `lib/style-anchor.ts` | 抽取高频词/句长/对话占比/情感强度/叙事节奏；注入 style_constraints 摘要（不回灌全文） |

三者在故事工作台（`/stories/[id]/edit`）以「运行」按钮触发，结果注入后续 AI 生成上下文。

### 4.5 创作工作台（结构化创作）

- **章节大纲编辑器**：`story_outline_nodes` 表，`id + parent_id + type + sort_order + content`；支持无限层级、上移/下移/指定位置插入，同级 `sort_order` 批量重排。
- **人物关系图谱**：`character_relations` 表（允许同对角色多条关系），前端 `components/RelationGraph.tsx` 用 d3 渲染节点 + 连线标签；关系类型：敌对/盟友/亲属/恋人/上下级/合作。
- **引入角色卡/世界卡**：`story_characters`、`story_worlds` 关联表，引入后 AI 自动参考其设定。
- **多分支叙事**：`story_branches` + `branch_nodes`，支持覆盖主线/插入主线/归档，合并走 `POST /api/stories/:id/branches/:branchId/merge`。
- **导入**：`lib/work-import-parse.ts` 用 mammoth/pdf-parse/word-extractor 从 Word/PDF/TXT 提取角色/世界/故事字段。

### 4.6 导出系统

| 格式 | 实现 | 细节 |
|------|------|------|
| Markdown/TXT | `lib/export-body.ts` | 按大纲顺序拼接正文 |
| EPUB | `lib/export-epub.ts`（JSZip） | EPUB 3 规范：mimetype、container.xml、package.opf、封面、目录 nav、分章 xhtml；封面缺失时生成默认封面（标题+作者+浅蓝背景） |
| PDF | `lib/export-pdf.ts`（PDFKit） | 自动分页、页眉标题 + 页脚页码；中文需 `storage/fonts/NotoSansSC-Regular.otf`，缺字体回退 Markdown |

- 命名规则：`{标题}_{作者}_{YYYYMMDD_HHMM}.{ext}`（`lib/export-shared.ts`）。
- 容错：超时/格式异常/超 50MB → 自动重试（指数退避）→ 仍失败回退 Markdown，响应头带 `X-StoryForge-Fallback`。

### 4.7 市场与推荐

**市场**（`app/(main)/market` + `app/api/feed/route.ts`）：

- 三类作品（故事/角色/世界）+ 搜索 + 标签/作者/评分/时间筛选；
- 排序：`latest`（发布时间）/ `updated`（更新时间）/ `recommended`（推荐分）。

**推荐打分**（`lib/recommendation-engine.ts`）：

```
score = 0.45 * like_score + 0.25 * follow_score + 0.20 * tag_match + 0.10 * freshness
```

- `like_score`：点赞+收藏归一化；`follow_score`：作者粉丝数归一化；`tag_match`：作品标签与用户偏好标签命中率；`freshness`：30 天半衰期 + 365 天封顶的时间衰减。
- 未登录用户：SQL 里等价的 `recommended` 排序表达式；登录用户：取 100 条候选，用 `buildUserProfile()`（基于点赞标签 + 关注作者）个性化重排取 30 条。
- 曝光/点击埋点：`feed_impressions` / `feed_clicks`。

### 4.8 轻互动、通知、评论与评分

- **互动**：点赞（`likes`，唯一约束 `(user,target_type,target_id)`）、收藏（`favorites`）、关注（`follows`）三合一 toggle 接口；热度计数回写作品表并失效市场缓存。
- **通知**：`notifications` 表（`type` + `payload_json` + `is_read`）；类型：被点赞/被收藏/被关注/作者更新；前端「我的」页 + 侧边栏未读角标（轮询 + 窗口聚焦刷新）。
- **评论**：`comments`（支持回复、点赞、举报）+ `comment_likes`；**评分**：`reviews`（1~5 星，`UNIQUE(user,target)`）；作品详情页 `TargetReviewSection` 统一展示。
- **作者主页**：`app/api/authors/[authorId]/(route|stats|works)` 展示简介、作品、粉丝数、二创关系。

### 4.9 内容审核

- 发布前：`lib/content-filter.ts` 敏感词片段扫描 + 长度限制；
- 对话中：输入输出双向过滤 + 系统层合规约束；
- 人工兜底：`/admin/moderation`（`moderation_items` 表），管理员可见，操作「通过/下架/驳回并备注」，写入 `basic_logs` 审计。

## 六、API 设计

### 6.1 统一响应结构

```json
{ "code": 200, "data": {...}, "msg": "ok" }
```

- 成功 `code=200`；参数错误 `code=400`（HTTP 400）；鉴权失败 401/403；限流 429（带 `Retry-After`）。
- 所有入参 zod `safeParse`，失败即 400。

## 七、安全设计

1. **鉴权**：JWT（jose, HS256, 7 天）+ HttpOnly Cookie，`getCurrentUserId()` 统一取身份。
2. **密码安全**：scrypt 加盐哈希 + `timingSafeEqual`。
3. **CSRF/跨站防护**：`middleware.ts` 拦截全部 `/api/*`，`isCrossSiteMutationBlocked` 校验 Origin/Host，跨站写请求返回 403。
4. **防重放**：敏感接口 `x-timestamp + x-nonce`，`lib/anti-replay.ts` 校验 5 分钟时窗 nonce 唯一（`used_nonces` 表）。
5. **越权防护**：写接口先鉴权再校验资源归属；管理员走 `lib/admin-auth.ts`（`STORYFORGE_ADMIN_USER_IDS`）。
6. **输入校验**：全量 zod + 文本长度限制 + XSS 过滤（`lib/text.ts`）。
7. **内容合规**：系统 Prompt 硬约束 + `content-filter` 双向扫描 + 审核台人工兜底。
8. **敏感信息**：手机号脱敏、API Key 不落日志、密钥不返回前端。
9. **限流**：登录/注册/生成接口按用户 + IP 双层限流。

## 八、性能与稳定性

| 维度 | 设计 |
|------|------|
| 缓存 | Redis 缓存推荐流（TTL 300s）、写后失效（`lib/invalidate-market-cache.ts`） |
| SQLite 并发 | WAL 模式 + 短事务；读多写少靠缓存 |
| 流式稳定 | SSE 心跳 15s + 总超时 180s + 停止生成 + 降级链 |
| 导出容错 | 自动重试（指数退避）+ 失败回退 Markdown |
| 故障降级 | 模型超时自动切备模型；RAG/冲突检测失败不影响主流程（try/catch） |
| 日志 | `lib/basic-logs.ts` 统一审计日志 |
| 健康检查 | docker-compose `healthcheck` 每 30s 探活，`restart: unless-stopped` |

```
    │
    ▼
Docker 容器 storyforge（node:22-slim，Next.js standalone，端口 3000）
    ├── storage/（数据卷：SQLite + 用户文件 + 导出物）
    └── 环境变量（JWT_SECRET / DEEPSEEK_API_KEY / REDIS_URL ...）
```

- **Dockerfile 三段式**：`deps`（apt 装编译工具 + `npm ci` + `rebuild sqlite3 --build-from-source`）→ `builder`（`npm run build` 产出 `.next/standalone`）→ `runner`（slim 镜像 + 非 root `nextjs` 用户 + `CMD ["node","server.js"]`）。
- **关键坑点**：sqlite3 原生模块必须保证「编译镜像」和「运行镜像」同发行版（node:22-bookworm），否则 glibc 不匹配加载失败。
- **国内访问外网**：`instrumentation.ts` 启动时 `setGlobalDispatcher(new ProxyAgent(proxy))` 统一走 `HTTPS_PROXY`。
